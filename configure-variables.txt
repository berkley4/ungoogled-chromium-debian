			1		Use system node package (safest on unstable)

BUILD_TS		0		0 = build system default (do nothing)
					1 = patch build/timestamp.gni to use a 'non-official build' timestamp (auto-updates monthly)
					2 = patch build/compute_build_timestamp.py to use a fixed timestamp (1750109210)
					The timestamp is build into the code and values of 1 and 2 might help the ccache hit rate
					as a newer timestamp could trigger re-compilation. A value of 1 is the default when CCACHE=1.

TIMESTAMP		<epoch>		Use a custom ten digit unix epoch for BUILD_TS=2 (needs to start with a non-zero digit)

MARCH			x86-64-v2	Matches MTUNE if MTUNE is set and MARCH is not specified
					Will not match MTUNE if MTUNE is set to generic
					Setting MARCH to generic will reset MARCH and MTUNE to their defaults
					Setting MARCH=0 will disable the march and mtune patches (for people with ancient pre-2011 CPUs)
					Set to x86-64-v3 if using Intel Haswell/AMD Excavator or newer CPUs (includes AVX, AVX2, ABM and BMI1)

MTUNE			generic		Matches MARCH if MARCH is set and MTUNE is not specified, unless MARCH is
					an x86-64 microarchitecture level (in that case MTUNE is set to generic)
					Will have no effect when setting MARCH=0
